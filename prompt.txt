Create a corporate document titled:

"Databricks Data Model Standards & Naming Conventions"

The document should serve as the official standard for Data Engineering, Data Analytics and Business Intelligence teams responsible for creating and maintaining tables in Databricks using Unity Catalog.

CONTEXT

The Databricks environment already has the Catalog and Schema structure defined.

Example:

agpt_insurance_dv_catalog.wkb_bus_operations_claimsmotor

The purpose of this document is not to define Catalogs or Schemas, but instead establish standards and best practices for:

- Table creation
- Naming conventions
- Data model design
- Data governance
- Metadata management
- Performance optimization
- Data quality
- Consistency across systems

Data sources may originate from:

- SAS
- ACAP
- Autoinforma
- GeoAPI
- CRM
- External APIs
- Excel files
- CSV files
- Relational databases
- Internal systems
- Third-party providers

The document should be written in professional English and be suitable for adoption as an enterprise-wide standard.

======================================================================

Establish the following standards:

- Mandatory use of snake_case

- No spaces
- No special characters

Provide examples of correct and incorrect naming conventions.

======================================================================
4. RAW TABLES
======================================================================

Raw tables represent data received directly from source systems.

Naming standard:

raw_<entity>_<source>_<brand>

Examples:

raw_claims_sas_ageas
raw_policies_sas_ageas
raw_vehicle_sales_acap_ageas
raw_vehicle_stock_autoinforma_ageas
raw_postcodes_geoapi_all

Explain the rationale behind the naming standard.

Describe what should and should not be performed at Raw layer level.
